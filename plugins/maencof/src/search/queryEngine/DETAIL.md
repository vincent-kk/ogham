# queryEngine — Contract

## Requirements

- collapse는 공통 query 경계에서 path-exact 제외 뒤, 절단 전에 한 번 수행한다. 검색·컨텍스트·평가 소비자의 별도 구현은 의미를 갈라놓으므로 금지한다.
- 같은 클러스터 문서는 독립 증거가 아니라 반복 관측이다. 그룹 점수는 활성 멤버 max를 승계하며 sum으로 문서 수 프리미엄을 되살리지 않는다.
- 대표를 활성 멤버로만 제한하는 대안은 사용하지 않는다. 어휘가 얇은 증류본이 활성화되지 않은 질의에서도 활성 필터를 만족하는 전역 최신 멤버가 승계해야 정제 지식이 반복 원본에 밀리지 않는다.
- 유일 어휘 매칭의 시드 지목은 최신 대표보다 우선한다. 지목은 시드별 budget 캡 이전에 판단하며, 여러 멤버에 매칭되는 주제어를 지목으로 올리면 증류본 승계가 깨지므로 금지한다.
- 전역 대표로 승계된 노드에 성립하지 않는 SA trace를 만들지 않는다. trace는 비우고 활성 멤버의 최소 hops만 전달한다.
- 접힌 활성 멤버와 전체 접힘 수는 구분한다. 제한된 멤버 목록은 펼치기 힌트이며 전체 증거 목록을 뜻하지 않는다.
- 시드가 닿은 클러스터와 확산만으로 나온 클러스터를 구별한다. 소비자의 자동 확장은 전자의 매칭 보고를 근거로 한다. 소비자 쪽 확장 조립 계약의 정본은 `mcp/tools/kgSearch/DETAIL.md`다.
- 전역 대표 수집은 관련 클러스터에 대한 그래프 1패스다. 별도 인덱스의 여러 갱신 경로 동기화 비용이 1패스 비용을 넘으므로 인덱스를 추가하지 않는다.
- 레이어·서브레이어·시간 필터는 collapse와 절단 전에 공유 경계에서 적용한다. 소비자의 post-slice 필터는 결과 수 미달을 만든다.
- clusterseed 앵커는 확산만으로 결과에 나타나지 않되 대표 승계 자격을 유지한다. 승계 자격 유지는 사용자가 확정한 결정이므로 바꾸기 전에 확인을 받는다. 평소에는 대표만, 특정 언급 때 내부를 보여주는 설계다.
- archived 키워드 시드는 강등한다. 본문이 빈 스텁이 태그 경쟁력으로 정제 지식을 밀어내지 않게 하되 직접 경로 지목은 존중한다.
- 탐색량은 collapse·절단 전 활성 노드 수이며 출력량과 구별한다. 캐시는 collapse와 절단을 마친 결과를 보관한다.
- 상대 IDF는 후보 union을 바꾸지 않고 흔한 토큰만 강등한다 — 동형이의어 노이즈 억제가 후보 손실로 바뀌지 않아야 한다.
- compound 시드는 실재하는 원형 완전 일치를 우선하며 분해 AND가 비었을 때만 저득점 OR로 폴백한다. 자연어 분해는 단어 OR와 인접 구를 함께 사용한다.
- 시드별 매칭 계수는 미해석 시드를 드러내므로 결과와 캐시에 항상 전파한다. 반복 횟수에 대한 maxHops 매핑과 쿼리 토큰 게이트는 공통 엔진이 소유한다.

## API Contracts

- 클러스터 대표 선정은 엔진 내부 계약이며 소비자에 복제하지 않는다. path-exact 결과 제외는 지목과 전역 대표 승계보다 우선한다.
- 지목은 budget 캡 이전의 시드별 유일 어휘 매칭으로 판단한다. 캡 때문에 하나만 남은 주제어 매칭을 지목으로 오인하면 증류본 승계가 깨진다.
- 결과 영향 옵션을 추가할 때 캐시 키도 함께 갱신한다. 키 구성과 무효화의 정본은 `queryCache/DETAIL.md`다.

## Acceptance Criteria

구체 동작의 수용 기준은 테스트가 고정하며, 공통 경계와 설계 이유는 위 계약을 따른다.
