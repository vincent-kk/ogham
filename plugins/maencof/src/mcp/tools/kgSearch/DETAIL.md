# kgSearch — Contract

## Requirements

- 기본 응답은 참조 메타이며 trace·본문은 opt-in이다. 응답이 LLM 컨텍스트를 소비하므로 기본형을 가볍게 유지한다. 쿼리 엔진 ActivationResult는 바꾸지 않고 메타 매핑만 이 핸들러가 소유한다.
- seed 해석 상태는 항상 보고하되 cap 이전의 어휘 매칭 계수를 쓴다. 미해석 원문을 구별할 수 있어야 빈 결과와 확산 실패를 혼동하지 않는다.
- sub_layer를 포함한 검색 필터는 query 엔진의 pre-filter다. 결과 절단 뒤 필터링하면 max_results보다 적은 결과를 조용히 만들므로 핸들러 post-filter로 옮기지 않는다.
- 접힘 표기는 엔진이 소유한 의미를 그대로 전달한다. 평소에는 대표만, 시드가 언급한 클러스터만 내부를 자동 확장한다. 확장은 랭킹·점수·결과 구성을 바꾸지 않아 평가 하네스와 독립적이다.
- expansion과 collapsedMembers를 함께 싣지 않는다. 같은 멤버를 중복 표현하면 토큰 비용만 늘어난다. 확장 클러스터와 멤버 수는 각각 상한을 둔다.
- cluster 모드는 SA 없이 활성·서고 멤버를 함께 열거한다. 서고 멤버 맵이 없는 구캐시는 활성 멤버만으로 동작하며 다음 빌드가 맵을 채운다.
- cluster 필터는 정렬·계수·절단보다 앞서 적용한다. 그렇지 않으면 오래된 매칭 항목이 최신 비매칭 항목에 밀려 유실된다. 큰 서고를 전부 받은 뒤 육안 선별하지 않도록 title·tags 주제 필터를 제공한다.
- cluster 페이지 크기는 호출자가 정하고 스키마 상한과 내부 방어선을 구별한다. 고정 최대량 반환은 큰 서고에서 가벼운 응답 원칙을 깨므로 사용하지 않는다.
- include_content의 파일 부재·읽기 실패는 해당 본문만 생략한다. 그래프가 없으면 재색인을 안내한다.

## API Contracts

seed와 cluster는 서로 다른 조회 모드이며 정확히 하나를 선택한다. cluster에는 시간창·match·offset을 적용하고 layer_filter·sub_layer·trace는 적용하지 않는다. match는 seed 모드에 적용하지 않으며 본문 opt-in은 두 모드가 공유한다.

cluster 페이지는 updated 내림차순·path 오름차순의 결정적 순서다. 같은 날짜의 문서가 페이지보다 많을 수 있으므로 날짜 단위 until 커서는 완주 수단이 아니다. offset을 반환 수만큼 늘리고 필터 적용 후 clusterSize에 도달했는지 확인한다. cluster 항목의 updated는 정렬 키이며 seed 응답과 의도적으로 형태가 다르다.

도구 설명은 호출자가 실제 도달 가능한 스키마 상한을 안내한다. 내부 방어선을 공개 최대값으로 안내하면 실행 불가능한 페이지를 계획하게 된다.

## Acceptance Criteria

행동별 결과와 경계값은 이 모듈을 검증하는 테스트가 고정한다.
