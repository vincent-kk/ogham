# directives — Contract

## Requirements

- 연결 기록은 등록한 저장소의 실경로를 담습니다. 다른 경로로 체크아웃한 저장소에서 복사된 묶음이 주입되는 것을 막기 위해 읽는 루트와 비교합니다. 같은 절대 경로에 복제된 체크아웃은 이 검사로 구분할 수 없습니다.
- 모든 연결 변경은 기존 기록 읽기부터 쓰기까지 하나의 잠금으로 보호합니다. 주입 시각의 갱신이 동시 실행된 비활성화를 되돌리는 일을 방지하며, 잠금에 실패하면 변경을 생략합니다.
- 사용자 소유 ignore 파일에 묶음 경로 제외가 빠져 있으면 파일을 보존하고 bind 응답에 경고를 담습니다. 자동 행위자 상태 생성과 달리 사용자가 명시적으로 지침 연결을 요청했으므로 등록은 진행합니다.
- 묶음은 한 워크플로 동안의 작업 지식입니다. 진입 문서 `index.md`가 있는 묶음은 구조화된 묶음이고, 없는 묶음은 파일 전체를 지침으로 다룹니다. 진입 문서의 이름을 꾸미지 않은 것은 에이전트와 사용자가 직접 고쳐 쓰는 문서이기 때문입니다. 그 대가로, 구조 없이 쓰던 묶음에 우연히 `index.md`가 있으면 구조화된 묶음으로 취급됩니다.
- 구조 위반은 쓰기를 막지 않고 응답에 드러냅니다. seiri의 훅은 도구를 차단하지 않으므로 문서 쓰기를 막을 수단이 없고, 남는 수단은 어긋남이 반드시 보이게 하는 것입니다.

## API Contracts

### 렌더링

- 렌더링 예산은 지침 블록 전체에 적용합니다. Claude는 문자 수를 사용하고 Codex 호출부는 UTF-8 바이트 측정 함수를 넘깁니다.
- 구조화된 묶음은 제목, 디렉터리의 절대 경로, 진입 문서의 본문, 그리고 압축 직후 읽어야 하는 문서 가운데 실제로 있고 비어 있지 않은 것의 이름을 적은 한 줄을 받습니다. 다른 문서의 본문은 넣지 않습니다. 묶음이 자라도 주입량이 일정해야 하고, 핵심 원칙의 전달이 에이전트의 읽기 행동에 기대지 않아야 하기 때문입니다.
- 압축 직후 읽어야 하는 문서는 파일 이름 규약으로 정합니다. 진입 문서의 표를 해석하지 않는 것은 표가 망가져도 안내가 유지되어야 하기 때문입니다.
- 진입 문서가 없는 묶음은 모든 파일의 본문을 받습니다.
- 블록 전체가 예산을 넘거나 어느 진입 문서가 자신의 상한을 넘으면 모든 묶음이 경로 안내로 바뀝니다. 묶음마다 제목과 디렉터리의 절대 경로를 한 줄씩 제공하고, 파일 수에 따라 안내가 길어지지 않도록 마지막 한 줄에서 진입 문서를 먼저 읽고 진입 문서가 없는 디렉터리는 `binding.json`만 빼고 다시 읽으라고 안내합니다. 상한을 넘은 진입 문서는 그 묶음의 경로 줄 뒤에 초과 사실을 한 줄로 알립니다.
- 한 묶음의 문서를 읽지 못하면 그 묶음만 경로와 읽지 못한 파일 이름으로 안내하고 나머지 묶음은 그대로 전달합니다. 묶음 하나의 고장이 다른 묶음의 지침까지 지우면 안 되기 때문입니다.
- 경로 안내의 길이는 예산과 비교하지 않습니다. 예산은 본문 방식을 고를지 정하는 기준입니다.

### 한도

- 진입 문서의 상한은 두 호스트에서 같은 바이트 수입니다. 같은 문서가 한 호스트에서는 통과하고 다른 호스트에서는 넘치는 일을 막습니다. 바이트로 세므로 글자당 바이트가 많은 언어는 같은 상한에 덜 들어갑니다.
- Codex의 블록 한도는 Codex가 훅 출력을 그대로 넘기는 기본 문턱 아래에 여유를 둔 값입니다. Codex는 훅 처리기마다 대략 2,500토큰까지 그대로 넘기고 토큰을 4바이트당 하나로 세므로 문턱은 10,000바이트입니다. 근거는 [output_spill.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/output_spill.rs)와 [truncate.rs](https://github.com/openai/codex/blob/main/codex-rs/utils/string/src/truncate.rs)입니다. 문턱을 넘기면 Codex가 본문을 임시 파일로 빼고 앞뒤 미리보기와 경로만 모델에 넘기며, 그 저장이 실패하면 잘린 글만 넘깁니다.
- 이 보장은 Codex의 기본 문턱에 한정됩니다. 사용자가 처리기의 문턱을 더 낮게 정했거나 문턱이 더 작은 버전이면 한도 안의 블록도 임시 파일로 빠질 수 있습니다.

### 점검

- 점검은 구조화된 묶음에서 상한을 넘은 문서, 진입 문서가 가리키지 않는 파일, 진입 문서가 가리키지만 없는 마크다운 문서, JSON 객체로 읽히지 않는 기록 줄, 읽을 수 없는 파일을 찾습니다.
- 진입 문서가 파일을 가리킨다는 것은 인라인 코드 스팬의 내용이 그 파일의 경로와 정확히 같다는 뜻 하나뿐입니다. 울타리 코드 블록 안의 글과 본문에 그냥 적힌 이름은 가리킨 것으로 보지 않습니다. 본문에서 이름을 문자열로 찾으면 더 긴 이름의 일부, 문장부호, 비 ASCII 글자마다 예외가 생기고, 없는 문서와 가리키지 않은 파일의 판정이 서로 어긋납니다.
- 없는 문서는 묶음 안을 가리키는 경로만 판정합니다. 빗금이 없거나 첫 구간이 묶음에 있는 디렉터리인 경로가 그렇습니다. 묶음 밖의 문서를 가리키는 경로를 위반으로 보고하지 않기 위해서입니다.
- 점검이 내용을 읽는 파일은 진입 문서와 두 기록뿐이고, 이들이 권한 때문에 읽히지 않으면 예외를 던지지 않고 위반으로 보고합니다. 그 밖의 문서는 내용을 읽지 않으므로 읽을 수 있는지도 보고하지 않습니다. 진입 문서를 읽지 못해도 파일 크기로 아는 상한 초과는 함께 보고합니다. 점검은 연결과 상태 조회에서만 실행합니다. 묶음을 끄거나 지우는 조작이 그 묶음의 내용을 읽을 수 있어야만 동작하면, 고장 난 묶음을 치울 수 없습니다. jsonl 기록은 첫 덧붙이기 때 생기고, 원칙·현황판·오케스트레이션 문서는 진입 문서의 틀이 미리 이름을 적어 두되 처음 필요할 때 만들므로, 이들은 없다는 이유로 보고하지 않습니다. 보고하면 진입 문서 하나뿐인 최소 묶음이 항상 위반으로 나옵니다.
- 메모장에 남은 줄 수는 위반이 아니라 회고가 남아 있다는 신호로 따로 셉니다.
- 압축 직후에는 진입 문서의 상한 초과만 알리고 나머지는 연결과 상태 조회의 응답이 알립니다. 훅 번들의 크기 여유가 거의 없어서 점검 전체를 훅에 넣지 않습니다.

### 덧붙이기

- 메모장과 이력은 한 줄에 JSON 객체 하나를 덧붙이는 기록이고, 시각은 호출자가 넘긴 시계 값으로 찍습니다. 에이전트가 직접 쓰면 줄 형식이 깨지고, 시각을 지어내고, 기존 줄을 고쳐 쓸 수 있기 때문입니다.
- 덧붙이기는 연결 변경과 같은 잠금 안에서 실행하고, 잠금을 얻지 못하면 쓰지 않습니다. 묶음 삭제와 만료 정리가 같은 잠금을 쓰므로 그 사이에 끼어들지 않습니다.
- 잠금 획득 중 삭제된 묶음 디렉터리가 다시 생길 수 있으므로, 잠금 안에서 지침 파일이 남아 있는지 확인하고 없으면 쓰지 않습니다.
- 대상은 링크를 따라가지 않는 방식으로 열고, 열린 디스크립터가 일반 파일인지 확인한 뒤 씁니다. 마지막 바이트도 같은 디스크립터로 읽습니다. 경로를 다시 열어 읽으면 쓰는 대상과 다른 것을 볼 수 있기 때문입니다.
- 기존 파일이 줄바꿈 없이 끝나면 줄바꿈을 먼저 넣어 두 객체가 한 줄에 붙지 않게 합니다. 기존 바이트는 바꾸지 않습니다.
- 막지 못하는 경우가 둘 있습니다. 묶음 디렉터리의 상위 경로가 실행 도중 바뀌는 경우와, 링크 비추적 열기가 없는 플랫폼에서 검사와 쓰기 사이에 대상이 바뀌는 경우입니다.

### 조작과 이식성

- 파일과 경로는 공통 이식성 계층을 사용합니다. 잠금 소유권 기록과 원자 쓰기 임시 파일은 지침 본문에서 제외합니다. 잠금 획득 중 삭제된 묶음 디렉터리가 다시 생길 수 있으므로 연결 기록을 쓸 때는 잠금 안에서 지침 파일이 남아 있는지 확인합니다. 묶음 삭제는 잠금 디렉터리도 제거하며, 잠금 해제 시 소유권 기록이 이미 없어도 성공합니다.
- `node:fs`의 `lstatSync`는 공통 API가 제공하지 않는 링크 비추적 항목 종류·크기·수정 시각 조회와 실경로 변환 후 입력 경로의 존재 확인에 사용합니다. `rmSync`는 묶음 및 잠금을 통째로 제거할 때 필요한 재귀 디렉터리 삭제에 사용합니다.
- `node:fs`의 `openSync`·`fstatSync`·`readSync`·`writeSync`·`closeSync`는 덧붙이기에 사용합니다. 공통 API에는 링크를 따라가지 않고 열어 같은 디스크립터로 확인하고 읽고 쓰는 기능이 없습니다.
- 검증 코드에서 `mkdtempSync`는 테스트 디렉터리 격리, `symlinkSync`는 경로 탈출 검증, `utimesSync`는 만료 기준 재현에 사용합니다. 이 조작과 재귀 삭제 및 항목 상태 조회는 공통 API에 해당 기능이 없습니다.

## Boundary Exemptions

### `utils` — 훅 번들용 직접 접근

- **Consumers**: `**/src/hooks/**`
- **Direct import**: `allowed`
- **Reason**: 공개 진입점의 재노출 그래프가 훅 번들에 포함되면 크기 상한을 넘을 수 있어 훅에는 필요한 파일만 포함합니다.
