# seiri

> 웨일스어 `saer`("장인")의 복수형. 만드는 손의 규율을 다루는 규칙.

**에이전트가 파악하기 좋은 코드 구조를 추종한다** — 이 하나를 제1원칙으로 삼는 Claude Code와 Codex용 플러그인입니다. 코드 작성·리뷰 규율·개발 방법론에 관한 소수의 규칙을 담고, 그중 고른 것만 저장소에 배포합니다.

English: [README.md](./README.md)

## 무엇을 하는가

선택한 규칙은 Claude의 프로젝트 규칙 파일 또는 Codex의 AGENTS.md 관리 영역에 배포됩니다. 하니스가 직접 읽으므로 seiri는 규칙 본문을 다시 주입하지 않습니다.

최초 스킬 선택은 사용자나 호스트의 일반 스킬 선택에 맡깁니다. 설명, 단독 추적·검증, 읽기 전용 리뷰, 간단한 수정에 개발 계획이나 원장을 강요하지 않습니다.

기본 **Skills only**(off)와 advisory는 자동 컨텍스트나 신규 관측을 추가하지 않습니다. 기존 참여가 다음 요청으로 이어지지 않도록 신뢰되는 턴·세션 경계의 무효화는 허용합니다. standard/strict는 세션 시작 시 워크플로우 체인·선출 문구·규칙/다이얼/드리프트 요약을 보여 주고, strict는 활성 바인딩이 없는 턴마다 체인 한 줄을 덧붙입니다. 작업 단위 보조(진행 줄·원장 갱신)는 진입 스킬(`write-plan`, `execute`)이나 명시 `start`가 runtime 도구로 작업을 바인딩할 때만 시작되며, pause·finish·다른 task로의 전환 전까지 이후 턴에도 유지됩니다. 바인딩되지 않은 작업에는 진행 줄·원장 갱신이 없습니다.

runtime은 명시적 저장소 절대경로와 작업 이름을 받습니다. accepted 응답은 입력 검증이며, 짝이 맞는 훅 ACK가 참여를 확정합니다. standard/strict에서 활성 바인딩은 새 사용자 턴에도 유지되며, 세션 경계·pause·finish·다른 task로의 진입 전환만 이를 끝냅니다. 기존 바인딩이 있는 같은 작업을 이어갈 때만 resume합니다. 남겨 둘 작업은 pause, 연결을 끝낼 작업은 finish하며 finish 자체는 완료 증명이 아닙니다.

원장은 선택 사항입니다. 활성 작업에 원장이 있으면 대응하는 Bash 호출의 CHECK/EXPECT로 증거를 기록하고, 다른 작업 원장은 건드리지 않습니다. 동일 증거는 반복 주입하지 않습니다. 검증은 주장과 변경 유형에 맞추며 여전히 유효한 결과를 재사용합니다.

actor 상태는 7일 무관측, 호출 기록은 24시간 뒤 만료됩니다. 호스트 귀속이 없거나 저장에 실패하면 보조를 생략합니다. 철회 상태와 대체 marker를 모두 저장하지 못한 장애 후에는 과거 참여가 복구될 수 있다는 한계가 있습니다. 두 호스트의 native ID·응답 형식은 기록했지만 이전 턴 이벤트를 새 턴 뒤로 강제 지연한 native interleave는 직접 관측하지 못했습니다.

## 설치

```
/plugin install seiri
/seiri:setup
```

`/seiri:setup` 은 사용 가능한 규칙 목록을 담은 로컬 설정 페이지를 엽니다. 저장 전까지 아무것도 쓰이지 않으며, **무엇이 바뀌는지 diff 로 먼저** 보여줍니다. 이 파일들은 저장소에 상주하는 지시가 되므로, 들어오기 전에 사용자가 결정합니다.

## 설계

**저장소의 진실을 소유하지 않습니다.** 어떤 검증 명령을 쓰는지, 임계치가 얼마인지, "완료"가 무엇인지는 테스트·CI·`CLAUDE.md` 의 몫입니다. seiri 는 그 값의 사본을 갖지 않습니다 — 사본은 드리프트하기 때문입니다.

**모델의 판단을 소유하지 않습니다.** 차단 훅도 승인 게이트도 없습니다. 규칙은 컨텍스트이고, 무엇이 컨텍스트일 뿐이며 무엇이 실제로 강제되는지를 플러그인이 숨기지 않고 표기합니다.

**모든 규칙은 물러섭니다.** 각 규칙은 같은 우선순위 사슬로 시작합니다 — 저장소의 명시 지침 > 저장소의 기존 관례 > 이 규칙. 충돌하면 규칙이 비켜섭니다.

**모든 규칙은 선택입니다.** 필수 규칙이 없고, 명시적 선택 없이 배포되는 것도 없습니다.

**문서는 세션의 응답 언어를 따릅니다.** 계획·게이트 원장·결정 기록·명료화 결과는 하니스가 응답에 설정한 언어로 쓰입니다 — seiri 는 자체 언어 설정을 두지 않습니다. 기계가 읽는 표지·식별자·코드는 원문을 유지하고, HTML 기사는 지정된 독자를, PR 본문은 저장소 관례를 따릅니다.

## filid 와의 관계

둘은 층위로 나뉩니다. [filid](../filid) 는 강제 가능한 구조 경계·임계·리뷰를 맡습니다 — 숫자와 그 숫자의 의미. seiri 는 방향을 맡으며, `architect`는 아키텍처 의도를 기록하되 검증하거나 강제하지 않습니다. 이 구분 덕분에 seiri 는 특정 아키텍처를 모르는 저장소에서도 단독으로 성립합니다.

## 스킬

직접 호출하는 것:

| 스킬                     | 용도                                             |
| ------------------------ | ------------------------------------------------ |
| `/seiri:setup`           | 이 저장소가 쓸 규칙 선택                         |
| `/seiri:architect`       | 요구사항·시스템 관점·결정을 지속 가능한 기록으로 |
| `/seiri:clarify-request` | 요청을 실행 가능한 검증 범위로 명확화            |
| `/seiri:scaffold-pr`     | 작업 시작 전에 빈 Draft PR 열기                  |
| `/seiri:finish`          | 끝난 작업을 통합할지 결정                        |
| `/seiri:explain`         | 개념과 관계 중심으로 코드 동작을 설명            |
| `/seiri:trace-change`    | 코드 변경을 독자를 위한 계층으로 설명            |

적용 범위에 맞으면 호스트가 선택할 수 있는 것 — 고정 체인은 강제하지 않습니다:

| 스킬                     | 용도                                  |
| ------------------------ | ------------------------------------- |
| `/seiri:write-plan`      | 지속적 계획이 필요한 큰 변경을 계획    |
| `/seiri:review-plan`     | 실행 전에 계획의 주장을 검증          |
| `/seiri:execute`         | 작성된 계획을 완료까지 수행           |
| `/seiri:implement`       | 동작·리팩터링·문서별 검증으로 구현           |
| `/seiri:trace-structure` | 판단 전에 연결관계와 데이터 흐름 추적 |
| `/seiri:trace-cause`     | 실패를 드러난 곳이 아니라 시작점까지  |
| `/seiri:verify`          | 완료를 선언하기 전에 주장 검증        |
| `/seiri:request-review`  | 범위를 고정해 리뷰에 넘김             |
| `/seiri:receive-review`  | 리뷰 피드백을 코드에 반영             |

## 로컬 개발 배포본

저장소 루트에서 shared provider와 seiri를 지정 빌드한 뒤 새 절대경로에 배포본을 준비합니다. 명령 전문은 [영문 문서](README.md#local-development-distribution)에 있습니다.

`node scripts/prepareSeiriDistribution.mjs --output <새-절대경로>`는 package allowlist의 정본·새 runtime만 복사하고 plugin-compiler로 adapters를 생성합니다. 기존 tracked adapter는 입력으로 재사용하지 않으며 생성물은 소스 커밋과 별도의 빌드 커밋에 커밋됩니다. `node scripts/checkSeiriAdapters.mjs`는 임시 배포본의 생성 결정성과 참조를 검사합니다.

로컬 수용은 공개 출시가 아닙니다. 배포 채널 결정과 그 채널의 설치 수용 전에는 버전 변경·공개 출시, 그리고 seiri 변경사항(소스와 커밋된 생성 bundle/adapter)을 marketplace가 읽는 Git ref로 push하거나 merge하는 것을 하지 않습니다.
