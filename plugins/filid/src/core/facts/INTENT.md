# facts — agent-submitted reference facts

## Purpose

에이전트가 제출한 파일별 사실을 코드를 해석하지 않고 검사해 저장하고, 저장된 사실과 현재 트리로 파일 상태를 판정한다. 소스 파일은 hash 계산과 문자열 존재 확인에만 byte로 읽는다.

## Conventions

- 판단 우선순위: 1. 확인할 수 있는 성질 2. 원인 파일 귀속 3. 좁히지 않는 쪽
- 파일마다 레코드 하나이고 제출은 교체다. 지우는 동작은 두지 않는다.
- 상태 판정은 순수 함수다. filesystem 사실은 호출자가 모아 인자로 넘긴다.
- 저장은 원자적 치환과 compare-and-set이며 hook의 lockless lock은 쓰지 않는다.
- 거부 응답에는 언제나 상태를 바꾸는 다음 행동이 하나 붙는다.

## Boundaries

### Always do

- 레코드를 받기 전에 hash 결속, 문자열 존재, 해석 경로 유효성을 검사
- 거부를 레코드 단위와 참조 단위로 구분하고, 참조 하나의 거부가 레코드를 버리지 않게 유지
- 호출자가 준 경로를 열기 전에 절대성·프로젝트 밖·symlink·일반 파일·크기를 검사
- 확인되지 않은 것은 통과가 아니라 그 파일의 미확정 상태로 표현

### Ask first

- 레코드 스키마, 저장 위치 또는 epoch 정의 변경
- 파일 상태 표와 `unknownFiles`의 의미 변경

### Never do

- 소스 파일을 구문으로 해석하거나 참조를 스스로 추출
- 어떤 명령도 실행 — `provenance.command`는 기록일 뿐이다
- 파일 내용이나 parser·schema 오류 원문을 응답에 싣기
- 제출로 선언된 범위를 넓히기
- project tree에 쓰기
