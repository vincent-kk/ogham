## **8\. Layer 5 재정의: 임시 수용소와 레이어 직교 허브**

### **8.1. 두 개의 공백, 하나의 레이어**

아키텍처 버전 1.0.0에서 Layer 5(맥락 메타데이터)는 인물(`persons/`)과 도메인(`domains/`) 정보를 분류하는 단일 목적의 보조 계층으로 설계되었다. Layer 3의 3차원 방향성 분할([§7](./07-l3-directional-expansion.md) 참조)과 함께 두 가지 구조적 공백이 확인되었다:

1. **미분류 정보의 부재**: 아직 어떤 레이어에도 속하지 않는 원시 정보(대화 조각, 임시 메모, 농담, 단편적 스크랩)를 수용할 공간이 없었다. 이러한 정보는 Layer 3이나 Layer 4에 억지로 배치되거나 아예 기록되지 못했다.
2. **교차 연결 메커니즘의 부재**: L3A/3B/3C로 분할된 외부 지식 간의 교차 연결을 수행할 구조적 허브가 없었다. 분할이 지식의 사일로화(Siloing)로 귀결되는 것을 방지하려면, 서로 다른 방향성의 지식을 특정 실행 맥락 안에서 통합하는 메커니즘이 필수적이다.

버전 2.0.0은 두 공백을 모두 Layer 5의 서브레이어(`buffer` / `boundary`)로 메우려 했다. **이 배치가 잘못이었다.** 두 공백은 성질이 정반대다 — 미분류 정보는 휘발성이고 격리되어야 하며, 교차 연결 허브는 영속적이고 최대한 넓게 퍼져야 한다. 한 레이어가 두 성질을 동시에 표상할 수 없다.

버전 3.0.0은 두 공백을 서로 다른 축으로 분리한다:

| 공백        | 답                        | 축                             |
| :---------- | :------------------------ | :----------------------------- |
| 미분류 정보 | **Layer 5 = 임시 수용소** | 레이어 (수직)                  |
| 교차 연결   | **허브 속성**             | frontmatter 속성 (레이어 직교) |

### **8.2. Layer 5: 미분류 정보의 임시 수용소**

Layer 5는 아직 범주화되지 않은 정보의 임시 수용 공간이다. 지식 관리 생태계에서 모든 정보가 생성 즉시 적절한 레이어로 분류되는 것은 비현실적이다. 일상적인 대화에서 건진 단서, 우연히 마주친 아이디어, 맥락이 불명확한 메모 등은 즉각적인 분류가 불가능하거나 불필요한 경우가 많다.

- **트리 구조:** `/05_Context/` 디렉토리. **평면 구조이며 서브레이어를 갖지 않는다.**
  - 시간순 또는 키워드 기반 명명 (예: `buf-snippet-2026-03-04.md`, `buf-chat-quantum-hint.md`)
  - 서브레이어가 하나뿐인 레이어에서 서브디렉토리는 방을 나누지 않고 복도만 만든다.
- **문서 스키마 (Frontmatter):**
  ```yaml
  layer: 5
  buffer_type: snippet | conversation | unclassified
  promotion_target: relational | structural | topical | L2  # 시스템이 제안하는 승격 대상
  source_context: "대화 중 멘션" | "웹 스크랩" | "세션 메모"
  expires: 2026-04-03                      # 기본 30일 후 만료
  ```
- **그래프 특성:** **Temporary 노드**. 다른 레이어와의 연결이 미확정 상태이다. 다른 레이어의 문서가 Layer 5 노드를 참조하는 것은 금지된다(참조 불안정성 방지). Layer 5 노드 자체는 잠정적 아웃바운드 링크를 가질 수 있다.
- **SA 감쇠 인자:** 0.45 (최저 — 미분류 정보가 그래프 전체로 새어나가지 않도록 격리한다). 계수의 방향은 [§8.4](#84-감쇠-인자의-방향)를 참조한다.

#### **수용 범위**

- 아직 범주화되지 않은 대화 조각 및 임시 메모
- 맥락이 불명확한 웹 스크랩 및 스니펫
- 농담, 일화, 인상적인 표현 등 분류 기준이 모호한 정보
- 세션 종료 시 보존 결정이 내려졌으나 적절한 레이어가 즉시 결정되지 않은 L4 노드

#### **승격(Promotion) 규칙**

| 승격 경로 | 조건                                    | 트리거                       | Level 0-1   | Level 2-3    |
| :-------- | :-------------------------------------- | :--------------------------- | :---------- | :----------- |
| L5 → L3A  | 인물 관련 정보로 분류됨                 | 사용자 분류 또는 시스템 제안 | 명시적 승인 | 제안 후 확인 |
| L5 → L3B  | 조직/집단 관련 정보로 분류됨            | 사용자 분류 또는 시스템 제안 | 명시적 승인 | 제안 후 확인 |
| L5 → L3C  | 주제/개념 관련 정보로 분류됨            | 사용자 분류 또는 시스템 제안 | 명시적 승인 | 자동 전이    |
| L5 → L2   | 이미 처리된 지식의 직접 내재화          | 사용자 판단                  | 명시적 승인 | 자동 전이    |
| L5 → 삭제 | `expires` 경과 AND `accessed_count` = 0 | SessionStart 정리            | 명시적 승인 | 제안 후 확인 |

`promotion_target`이 레이어 번호가 아니라 서브레이어 이름을 담는 이유가 이 표에 있다. 승격 대상은 L3A·L3B·L3C를 구분해야 의미가 있으며, 셋을 `3`으로 뭉개면 승격 규칙이 표현할 수 있는 것을 스키마가 표현하지 못한다.

시스템의 자동 분류 제안은 다음 휴리스틱에 기반한다:

- Frontmatter의 `tags`에 인물명 포함 → L3A 제안
- 조직/팀/커뮤니티 키워드 탐지 → L3B 제안
- 기술/학문/개념 키워드 탐지 → L3C 제안 (기본값)
- AI 기반 내용 분석으로 분류 정밀도 향상 (Phase 3, 선택적)

> **미해결 — 진입점 부재**: 실측 vault(tirnanog, 2026-08-03 기준 1020 노드)의 Layer 5 문서 수는 0이다. 규칙은 "분류가 애매하면 L5"를 MUST로 지정하는데 한 건도 생기지 않았다. 가설은 두 가지다 — (a) L5로 보내는 전용 진입점이 없다, (b) L4(763 노드)가 이미 버퍼 역할을 흡수했다. 어느 쪽인지는 버전 3.0.0 전개 후 재측정해야 판단할 수 있다. (b)로 확인되면 이 절 전체를 폐지하고 해당 MUST 규칙도 함께 걷는다.

### **8.3. 허브: 레이어 직교 속성으로서의 경계 객체**

수잔 스타(Susan Leigh Star)가 창안한 '경계 객체(Boundary Objects)' 이론⁵⁸은 서로 다른 지식 체계나 집단적 경계를 가로질러 의사소통과 지식 공유, 의미 생성을 가능하게 해주는 아티팩트(Artifact)를 다룬다. 혁신 프로젝트에서 프로토타입, CAD 도면, 공유 데이터베이스, 대시보드 등이 대표적인 경계 객체로 기능한다.⁵⁸ PKM 환경에서는 **'메타데이터를 통한 구조적 링킹 노트'** 또는 **'프로젝트 MOC(Map of Content)'**로 발현된다.

**경계 객체는 레이어가 아니라 역할이다.** 버전 2.0.0은 이를 `L5-Boundary` 서브레이어로 구현했으나, 같은 문서가 스스로 반례를 인정하고 있었다 — _"`persons/`의 인물이 여러 조직(L3B)과 여러 주제(L3C)에 걸쳐 활동하는 경우, 해당 인물 노드는 사실상 Boundary 역할을 수행하게 된다."_ 실무에서도 같은 신호가 나왔다: 이 vault에서 MOC는 두 번 모두 L3-structural에 만들어졌고, L4 `projects/`의 프로젝트 문서들도 각자의 허브를 필요로 한다.

허브임은 문서가 **어떤 종류의 지식인가**(레이어)와 독립된, **어떤 역할을 하는가**의 문제다. 따라서 레이어 직교 frontmatter 속성으로 표현한다.

- **트리 구조:** 없음. 허브는 자신이 속한 레이어의 자리에 그대로 있는다.
- **문서 스키마 (Frontmatter):**
  ```yaml
  hub: true
  hub_kind: project_moc | cross_domain | synthesis | study_hub
  purpose: "프로젝트 Alpha의 인물·조직·기술 통합 대시보드"
  ```
  - `purpose`는 `hub: true`일 때 필수다. 허브의 존재 이유가 frontmatter에 있어야 `kg_context`가 본문을 열지 않고도 그 역할을 전달할 수 있다.
  - Layer 5 문서는 허브가 될 수 없다. 임시 수용소는 다리가 되지 않는다.
- **그래프 특성:** **Bridge 노드 (높은 fan-out)**. `CROSS_LAYER` 엣지 타입으로 서로 다른 방향성의 지식을 특정 실행 맥락 안에서 통합한다. 대상 선정은 **태그 겹침**이며, 노드당 `MAX_CROSS_LAYER_EDGES_PER_NODE` 상한을 적용한다. 레이어 필터는 두지 않는다 — 허브가 무엇을 이을지는 태그가 이미 말하고 있고, 레이어 목록을 따로 받으면 같은 사실을 두 곳에서 관리하게 된다.
- **SA 감쇠 인자:** 0.95 (최고 — 다리는 가장 넓게 퍼져야 한다). `CROSS_LAYER` 엣지 멀티플라이어는 0.45다 — 태그 겹침에서 기계가 추론한 엣지이므로 저자가 쓴 `LINK`(1.0)나 디렉토리 계층(0.8) 아래에 온다. 허브가 자기가 색인한 본문 문서를 밀어내면 허브의 값이 사라지기 때문이며, 이 값은 골든셋 스윕으로 확정했다([QGA-SA 명세 §4](../TOOL/Query-Gated-Accumulative-Spreading-Activation/01-algorithm-specification.md)).

#### **경계 유형과 통합 메커니즘**

경계 객체 이론은 세 가지 지식 간 경계 유형을 구분한다:⁶⁰

| 경계 유형                     | L3 서브레이어 간 갈등 요소                                            | 경계 객체 적용 예시                                                         |
| :---------------------------- | :-------------------------------------------------------------------- | :-------------------------------------------------------------------------- |
| **구문론적 경계** (Syntactic) | L3A(전문가의 구두 조언)와 L3C(텍스트 기반 학술 논문) 간의 형식적 차이 | 조언 내용과 문헌의 핵심을 공통 태그 및 용어집으로 통합 정리한 요약 노트     |
| **의미론적 경계** (Semantic)  | L3B(조직의 관행적 언어)와 L3C(보편적 학술 언어) 간의 해석 차이        | 조직 내에서 해당 학술 개념이 어떻게 쓰이는지를 재정의한 매핑 다이어그램     |
| **화용론적 경계** (Pragmatic) | L3A(개인의 이해관계)와 L3B(조직의 목표) 간의 실천적 이해 충돌         | 개인의 성과 목표와 조직의 KPI를 동시에 충족시키기 위한 프로젝트 기획서(MOC) |

이 삼분류는 **분석 도구이지 스키마 필드가 아니다.** `hub_kind`는 문서의 종류(`project_moc` 계열)를 담고, 이 문서가 어떤 경계를 가로지르는지는 `purpose`가 한 줄로 서술한다. 호출자에게 매번 구문론/의미론/화용론을 판정하게 하는 것보다, 무엇을 통합하는지 직접 쓰게 하는 편이 정확하다.

행위자-네트워크 이론(ANT)의 언어로, 분할된 각 행위자(사람, 집단, 개념)들은 PKM 시스템 내부에서 이 허브를 '의무 통과점(Obligatory Passage Point, OPP)'으로 삼아 상호작용하고, 서로를 변형(Translation)시키며 새로운 지식 네트워크의 질서를 확립하게 된다.⁴⁹

### **8.4. 감쇠 인자의 방향**

감쇠 인자 `d`는 확산 활성화 문헌의 표준 정의(`A[j] = A[i] · W[i,j] · d`)를 따른다. 노드가 이웃으로 내보내는 활성량에 **곱해지는 값**이므로 — 구현에서는 `outMass = a(i) · α · d(i) / |N(i)|` — **값이 클수록 넓게 퍼진다.** 감쇠되는 양이 아니다.

이 방향을 명시하는 이유는 버전 2.0.0에서 실제로 뒤집혔기 때문이다. 이 문서의 이전 판은 "감쇠 인자가 높다"를 "많이 감쇠된다"로 읽고 Buffer 0.95(최소 확산 의도)와 Boundary 0.60(광범위 확산 의도)을 적었다. 구현은 표준 정의대로 곱셈 계수로 쓰므로, 격리해야 할 미분류 정보가 가장 넓게 확산되고 다리 역할을 해야 할 경계 객체가 그래프에서 전파를 가장 많이 막는 노드가 되어 있었다. 숫자는 설계와 일치했고 의미만 반대였다.

| 노드                   | 감쇠 인자                                             | 근거                                   |
| :--------------------- | :---------------------------------------------------- | :------------------------------------- |
| L1 (정체성 코어)       | 0.5                                                   | 코어가 모든 질의에 딸려 나오면 안 된다 |
| L2 (파생된 자아)       | 0.7                                                   |                                        |
| L3 (외부 지식)         | 0.8 (relational 0.75 · structural 0.8 · topical 0.85) |                                        |
| L4 (행동 맥락)         | 0.9                                                   | 실행 맥락은 넓게 연결된다              |
| L5 (임시 수용소)       | 0.45                                                  | 미분류 잡음의 격리                     |
| **허브** (`hub: true`) | **0.95**                                              | 레이어·서브레이어 값을 덮어쓴다        |

축은 레이어 번호에 단조롭지 않고 U자형이다 — 코어와 미분류라는 양 극단이 좁게, 중간의 실질 지식이 넓게 퍼진다. 레이어 번호는 확산 적합성의 척도가 아니기 때문이다.

L5·허브 값은 골든셋 스윕이 계측으로 뒷받침한다: L5 는 0.25–0.6, 허브는 0.75–1.0 이 평탄구간이며 채택값은 그 안에 있다. 계측 절차와 응답면은 [QGA-SA 명세 §4](../TOOL/Query-Gated-Accumulative-Spreading-Activation/01-algorithm-specification.md)에 있다.

우선순위는 `hub` > `sub_layer` > `layer`다. 알고리즘 정의는 [QGA-SA 명세 §4](../TOOL/Query-Gated-Accumulative-Spreading-Activation/01-algorithm-specification.md)에 있다.

### **8.5. 다른 레이어와의 상호작용 패턴**

| 상호작용              | 방향             | 설명                                                                    |
| :-------------------- | :--------------- | :---------------------------------------------------------------------- |
| L5 → L3A/B/C          | 승격             | 미분류 정보가 분류되어 적절한 서브레이어로 이동                         |
| L5 → L2               | 직접 내재화      | 이미 처리된 지식이 바로 파생된 자아로 승격 (드문 경우)                  |
| L5 → 삭제             | 만료             | 설정된 기간 경과 후 미참조 정보 삭제                                    |
| 모든 레이어 → L5      | 금지             | 임시 수용소 참조는 불안정성 유발                                        |
| 허브 ↔ 태그 겹침 노드 | 양방향 교차 연결 | 레이어와 무관하게 `CROSS_LAYER` 엣지 형성                               |
| 허브 ← L4             | 프로젝트 생성    | 행동 맥락에서 새로운 허브(프로젝트 MOC) 생성. 허브는 L4에 그대로 있는다 |

`persons/`·`domains/` 디렉토리는 폐지한다. 버전 2.0.0은 이들을 "Boundary 객체의 특수한 인스턴스"로 유지한다고 했으나, 실측 vault에 두 디렉토리는 존재하지 않으며 인물 메타데이터는 L3A(relational)가, 도메인 분류는 `domain` frontmatter 필드가 이미 맡고 있다. 유지 대상이 없는 유지 조항이었다.

이 재정의를 통해 Layer 5는 지식 생태계의 **입수 관문**이라는 하나의 역할에 집중하고, **통합 허브**는 레이어에 묶이지 않은 채 필요한 자리에서 발현된다.
