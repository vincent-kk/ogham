# rule-slim-r2 — 4단계: 앵커 복원 변형 A/B (public-contract R2p · reuse-first R2r)

> 2026-08-02. 3단계 종료 후 사용자 결정: "지금 규칙이 최적이라는 확신이 없다" — 두 표적 모두 변형을 제작해 게이트하고 **통과분만** templates에 반영한다. 커밋은 사용자 결정.

## 0. 전역 제약 (모든 태스크가 상속)

**설계 원칙 — 복원, 발명 아님**: 변형은 v1(R1)에 있다가 v2 압축에서 삭제된 요소의 복원만으로 구성한다. 신규 문장 발명은 이번 범위 밖(근거 없는 재작성 방지 — 사용자 합의).

**diff 분석 결과(변형의 근거)**: v1↔v2에서 규범·근거 산문은 전부 보존됐고, 삭제된 것은 (a) 절 첫머리 볼드 테제, (b) Ask-yourself 앵커뿐이다. 따라서 iL의 R1 우위 원인 후보는 wildcard 3-근거(양쪽에 있음)가 아니라 §2의 볼드 테제 `**A contract you cannot enumerate is not a contract.**` + 표적형 Ask-yourself `"Can I read the public surface without resolving a wildcard?"` 두 앵커다. reuse-first의 표적형 Ask-yourself는 이미 무하중 실측(R2 2/10 vs R3 5/10)이므로, 이 실험은 "앵커 하중이 규칙별로 다른가"를 판별한다.

**기준선 = arms/R3**: R3(= 채택 R2에서 reuse-first Ask-yourself만 제거)는 현행 배포본(templates == .claude/rules)과 14종 바이트 동일해야 한다 — U1이 검증한다. iC 기준선은 stage3의 R3 n=10을 재사용하고, iL 기준선 R3×8만 신규로 돈다.

**R1 합산 규약**: R1 암은 1단계부터 바이트 불변이므로 기존 런을 합산한다 — iL R1 기존 3런(6/9·full 2), iC R1 기존 3런(9/9·full 3). 신규 rep은 t4부터. 구 R2 런은 어느 판정에도 합산하지 않는다(reuse-first 바이트 불일치).

**판정 기준 (사전 정의 — 실행 후 변경 금지)**: 주지표는 full-pass 비율(hidden 만점 런 비율).

- **R2p 채택**: iL에서 `rate(R2p) ≥ rate(R3) + 25%p` **이고** `rate(R2p) ≥ rate(R1) − 12.5%p`.
- **R2r 채택**: iC에서 `rate(R2r) ≥ rate(R3) + 25%p`.
- **v1 복원 회부**: R1이 같은 이슈에서 {R3, 변형} 모두를 +25%p 이상 이기면 해당 규칙의 v1 문면 복원을 사용자 결정으로 회부.
- 어느 조건도 미충족 → 현행 유지, "iL R1 우위 재현 안 됨(노이즈 추정)" 또는 "재현됐으나 복원 앵커 무효"로 기록.
- 한계 명시: n=8에서 25%p는 대략 1σ~1.5σ — 이 게이트는 채택 결정 절차이지 통계적 유의성 주장이 아니다. 결과 문서에 그대로 적는다.

**벤치 격리 규약**: stage3 §0과 동일(무개입 프롬프트, haiku, `subagent_type: general-purpose`, prepare 출력 그대로, FINAL.md 저장 관례, grade.mjs 채점, 웨이브 8~10, 실패 시 같은 rep 1회 재시도). 로그는 `<SCRATCH>/results-stage4.jsonl` 단일 파일, 실행 디렉터리 `<SCRATCH>/bench-runs-stage4/`.

**불변식**: 변형 파일도 rule-invariant 계약 유지 — `> **Precedence**:` 접두, `rests on a property`, B6 쌍, 러너명 금지, 숫자 임계 금지(`8 lines` 예외는 function-boundaries 소관), LF. U3에서 templates 반영 시 `yarn workspace @ogham/seiri test:run`이 기계 검사.

## 2. Name every re-export

**A contract you cannot enumerate is not a contract.** Wildcard re-exports hide the surface three ways: a new symbol in an internal file silently widens the contract; duplicate names across re-exported files drop silently; and text tools lose the symbol list at the boundary.
